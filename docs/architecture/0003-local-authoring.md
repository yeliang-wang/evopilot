# Native local authoring and assembly

The parent native-edit checkout owns canonical compatibility bytes, integration tests, developer documentation and assembly scripts. Its child gitlinks may be unpopulated while parent source work is qualified. A parent scope does not authorize edits throughout the workspace or inside child repositories.

Qualify each child as a separate project and explicit file scope before a Runtime-owned request. Child source check/build/test uses only its owned source, pinned vendor and exact dependencies. The parent remains the sole generator of canonical vendor copies. Native editing does not change the old provider or redirect its pending requests, receipts or daily state.

The authorized assembly operator populates all three independent local child repositories, integrates their reviewed source and exact gitlinks, then runs the full populated parent build/check/test and local artifact rehearsal. An unpopulated parent cannot claim populated-suite success. Component locks record clean exact local HEADs, parent source commit and shared contract digest only after index gitlinks match.

Local artifacts and assembly evidence confer no acceptance, release or GitHub authority. Remote URLs, GitHub activation and eventual unified Expert/plugin distribution remain separate pending stages. Preserve existing roadmap, target, security and approval requirements.
