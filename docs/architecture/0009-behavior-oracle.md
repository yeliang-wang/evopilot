# Independent behavior oracle

V08-T3 supplies V08-E11/E13 evidence before Runtime's V08-T4 reconstruction. Harness retains an independently reviewed oracle, its exact inventory/specification binding and immutable evaluation claims. All cases are mandatory. The oracle covers each non-excluded observable behavior facet, declares exact observations and any numeric tolerance, and retains deliberately wrong observations to test that its comparisons are effective. A newly reviewed profile is a new digest; changing the required cases never edits historical results.

The oracle content digest is independent of the inventory digest, avoiding a circular pin. The frozen inventory pins that oracle content; a separate binding joins the inventory and specification to the reviewed oracle. Original source, hidden expected observations and negative controls are reviewer material, never part of the builder's specification export.

Evaluation accepts an attempt identifier, not caller-supplied observations or PASS flags. A trusted host callback must read a protected Runtime receipt and verify the output bytes before returning it. The callback is absent by default. Harness validates scope, exact input/environment/dependency pins, receipt digest, full case identities, actual observations and current pins. It compares output, state, errors and ordered effects independently. Missing cases, unsupported observations, nonterminal receipts, source-assisted input, synthetic evidence or absent isolation remain explicit failures/incomplete outcomes. No oracle result alone grants L3, project completion or release.

The additive observation `execution` member identifies the approved reconstruction plan, original claim, clean execution workspace and retained receipt. Runtime seals it from its own records after adapter reinspection; an observer cannot substitute different identities. Old observations remain valid historical records. L3 selection requires this execution identity and at least two distinct clean attempts. Assessment freshness rereads the protected observations and requires the exact digests assessed by the retained oracle; it does not silently evaluate changed software against an old PASS.

A durable claim precedes provider reads. Exact request replay returns the original claim without another provider invocation. A lost response is inspected by ID; explicit reconciliation marks an unfinished evaluation incomplete without rerunning work. Late responses cannot overwrite reconciliation. Reads are bounded by the existing usability deadlines and JSON limits. Results and their case denominator are retained; new pins make the current view stale while preserving historical bytes.

The implementation uses Harness's existing extension store and candidate schema marker 7. Released v0.7 writers reject that marker. Parent-generated additive contracts are shared through public packages; frozen native-v1 standards and daily data remain unchanged. This stage implements the evaluator and technical E2E; actual protected Runtime adapter receipts, independent real-project semantic review and two clean reconstructions remain separate required evidence.
