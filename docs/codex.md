# EvoPilot v0.1 Preview in Codex

The candidate exposes one unified Expert entry and the `evopilot_v01_preview` MCP namespace. Tool names start with `evopilot_v01_`. Ordinary chats leave Expert off (`allow_implicit_invocation: false`).

After the [local installer](installation.md) has installed the bundle and the operator has explicitly registered the preview, select **EvoPilot v0.1 Preview** and submit an EvoPilot task. This supplies explicit activation intent for the current chat without a second enable confirmation. You can also explicitly request “Enable EvoPilot v0.1 Preview for this chat.” Pure information or guide requests remain passive. Inspect the returned session id, adapter PID, current session activation, and separate verified running connection identity, including installation, component versions and workspace. Explicit activation starts or reuses the shared connection. A daemon started by another chat does not activate this chat.

`inspect` may perform passive authenticated health inspection. Initialize, ping, tools/list and guide require no live connection and create no workspace or control state. Guide can help choose a scenario before activation. Product request, dispatch, reconcile and capabilities require current-session activation. Deactivate clears only that session flag; closing the chat or EOF does not stop the shared instance.

The executable is `node plugins/codex/server.mjs --config <canonical-json-path>`. The configuration is loaded lazily through the existing connection client. The source `mcp.template.json` is portable installer data. `manage-preview.mjs install` renders the installed `.mcp.json` with managed absolute paths and verifies the complete installed configuration. Registration is an explicit operator action: `codex plugin marketplace add ROOT --json`, then `codex plugin add evopilot-v01-preview@evopilot-v01-preview-local --json`. Installation itself performs no activation or registration. See [installation and removal](installation.md) and [recovery](recovery.md).

All eight tools return the namespace/session identity and safe correlation. Request takes `{owner,envelope:{operation,scope,input,requestId?,expectedRevision?}}`; owner is runtime, harness or ontology. Dispatch/reconcile take `{args:{scope,id,requestId,expectedRevision}}`. Operational payload validation remains with each owner. No tool accepts connection paths, credentials, callback code or approval shortcuts. Classification start/reanalyze are awaited requests; read their current state separately.

Transport is newline JSON-RPC, negotiated version 2025-06-18, with 1 MiB input lines, 8 MiB serialized responses and a single in-flight request with stream backpressure. Errors omit provider exception text and credentials. UNKNOWN retains request correlation: inspect the owner's receipt/run/classification state and reconcile, never blindly redispatch.

A stale or mismatched connection requires operator diagnosis and explicit recovery via the existing connection controls. The adapter never deletes control data or stops an unrelated daemon. No trusted classification or Catalog callbacks are automatically configured.

See [first journey](first-journey.md), [composition](product-composition.md), and [core guide maintenance](../expert/core/README.md). Local protocol tests and prior M0 evidence do not establish current Desktop acceptance. Current product/Host acceptance status is supplied separately in an exact candidate-bound local report and its real receipts; see [report verification](testing.md). Without that report, no acceptance claim is made.
