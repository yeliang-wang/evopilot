# v0.8 Expert workflow

This guide routes the implemented candidate interfaces. It does not declare release acceptance or award a project level. Resolve these references against the verified installation root.

| Scenario | Entry | Expected evidence |
| --- | --- | --- |
| V08-U01 | `guide(asset-consumption)` | Independent asset consumption and scoped domain answers |
| V08-U02 | `guide(ontology-reverse)` | Purpose and level admission before reverse modeling |
| V08-U03 | `guide(usability-assessment)` | Exact semantic evidence and independent level assessment |
| V08-U04 | `guide(controlled-reconstruction)` | Protected actual reconstruction and fixed independent oracle |
| V08-U05 | `guide(reconstruction-recovery)` | Original receipt reconciliation and bounded recovery |
| V08-U06 | `guide(asset-feedback-review)` | Substantive asset evolution and retained compatibility |

Reuse explicit project intent before asking questions. Read-only consumption does not create a modeling candidate. Formal reverse modeling requires the durable purpose/scope/exclusions/target/independent-inventory binding described in [the modeling gate](architecture/0007-modeling-intent-gate.md); owner APIs reject missing or stale bindings.

L1 means domain understanding, L2 means a reviewed implementation specification, and L3 means that the exact assets supported independent reconstruction passing the declared equivalence profile. These cumulative EvoPilot levels apply to a named slice. Templates, schema conformance and software publication do not establish a verified level. Report target, current verified level or null, status, pins, gaps and limitations separately.

For [standalone consumption](asset-service.md), authenticate the explicit project scope, resolve immutable versions, follow all cursors, and verify exact export closure offline. Keep normative specification projections and omissions separate from original packages. Use source-grounded definitions for domain questions; missing or conflicting facts stay unresolved. v0.8 does not compute production metrics.

Harness owns semantic and behavioral assessment through its [usability API](../projects/evopilot-harness/docs/usability.md). Runtime owns the [reconstruction plan and receipts](../projects/evopilot-runtime/docs/reconstruction.md). Configure trusted installation providers before using their execution/evidence operations. The ordinary connection has no automatic authenticated builder binding. Public JSON cannot register a provider or supply a PASS observation.

Follow [controlled reconstruction](architecture/0010-controlled-reconstruction.md): pin assets-only inputs, an independent withheld oracle, executor/model/configuration/environment and cumulative budgets. Preserve failed attempts, source/previous-output isolation, actual stage results and unavailable usage. Two distinct clean successful reconstructions and complete fixed oracle results are required for L3; source-assisted audits and synthetic mechanics cannot replace them.

On lost response or UNKNOWN, inspect the original receipt and reconcile without generation replay. A terminal failure may enter an actually authorized bounded recovery plan; old consumption and uncertainty remain recorded. Sixty minutes is the currently supported cumulative plan ceiling, not an industry-prescribed duration. Existing authorization covers routine unchanged steps; a new semantic or authority decision must concern a concrete prepared object.

For substantive evolution, preserve the original successful slice and immutable assets/results, review the exact changed specification, and run new requirements plus retained compatibility checks. Changed pins invalidate current claims until revalidation. Native package, project completion and software-release decisions retain their separate meanings. No graphical frontend work is included before v1.0 release.
