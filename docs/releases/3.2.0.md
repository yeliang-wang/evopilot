# EvoPilot v3.2.0 Deferred Candidate Notes

Status: **NOT RELEASED; INHERITED BY v4.0.0**

This completed v3.2.0 development scope was not published as a standalone release. Its Bundle-consumer guarantees are preserved as mandatory v4.0.0 acceptance. The implementation consumes the product-neutral assets published by `evopilot-harness v3.0.0`: EvoPilot remains a read-only execution control plane, discovers published Catalogs, matches a Profile, resolves one immutable Bundle, and proves that exact Bundle closure again before execution.

## Added

- Registry v2 and Catalog v3 dynamic read-only parsing.
- Published `HarnessComponent`, `HarnessProfile`, and `HarnessBundle` API projections.
- Profile matching from classification, positive concepts, negative concepts, and declared in-scope/out-of-scope boundaries.
- `bindingMode=immutable-bundle` goal-plan bindings with pinned Bundle, Profile, and Component ids, versions, and digests.
- Bundle execution plan, constraints, required evidence, and blocking validators in Harness-layer GoalTargets.
- Bundle closure revalidation before Goal Loop creation and every Loop iteration.
- `HARNESS_BUNDLE_BINDING_INVALID` and `HARNESS_BUNDLE_DIGEST_MISMATCH` consistency blockers.
- Bundle/Profile/Component and planning/current Catalog digest evidence in Loop context and iteration evidence sets.

## Compatibility

- Registry v1 and Template Catalog v1 remain readable.
- Legacy Template selection uses `bindingMode=legacy-template` and does not claim immutable Bundle compliance.
- Adding unrelated assets to a Catalog does not invalidate an already planned Bundle when the bound Bundle closure is unchanged.
- Harness lifecycle, evolution, review, approval, signing, and publication remain owned by `evopilot-harness`.
- EvoPilot Dashboard is not changed or released as part of this version.

## Configuration

Point EvoPilot at a Registry published by `evopilot-harness v3.0.0`:

```bash
EVOPILOT_HARNESS_REGISTRY_CONFIG=/opt/evopilot-harness/harness-registry.yaml
```

## Distribution

There is no v3.2.0 tag, GitHub Release, npm publication, installer, or container release to install. Use the latest published release documented in the root README, or wait for an accepted and separately authorized v4.0.0 release.
