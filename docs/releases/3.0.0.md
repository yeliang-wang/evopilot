# EvoPilot v3.0.0 Release Notes

EvoPilot v3.0.0 is the strict Harness boundary release. Harness lifecycle management moves out of EvoPilot and into `evopilot-harness`; EvoPilot reads only published Harness Catalog directories and uses them during goal planning.

## What Changed

- Removed EvoPilot Harness lifecycle CLI and API surfaces.
- Kept only read-only Catalog APIs:
  - `GET /api/v1/harness/catalogs`
  - `GET /api/v1/harness/catalogs/{catalogId}`
- Added `GoalPlan.selectedHarness` evidence with Harness id, version, domain, catalog id, catalog digest, entry path, entry digest, match score, and match reasons.
- Updated CLI and AI Agent docs so third-party agents operate projects through onboarding, preflight, `target plan`, owner approval, and `target run`.
- Updated package versions, installer defaults, OpenAPI metadata, Helm metadata, and distribution docs to `3.0.0`.

## Compatibility

- Compatible Dashboard: `v3.0.0` or later.
- Compatible `evopilot-harness`: `v1.0.0` or later.
- Compatible CLI/client/contracts packages: `3.0.0`.

## Migration

1. Publish a usable Harness in `evopilot-harness`.
2. Configure EvoPilot with `EVOPILOT_HARNESS_CATALOG_DIR` or `EVOPILOT_HARNESS_CATALOG_DIRS`.
3. Use `GET /api/v1/harness/catalogs` to verify Catalog visibility.
4. Generate a new `target plan`.
5. Review `plan.selectedHarness` and the Alpha/Beta/RC/GA phase plan before approval.

```bash
git diff --check
```

## Rollback

Rollback to `v2.5.0` or the previous image digest, then verify `/health`, `/ready`, project onboarding, target planning, release decisions, and Dashboard compatibility. If rolling back from v3, remember that v2.5.0 still exposed in-EvoPilot Harness lifecycle operations.
