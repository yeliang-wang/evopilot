# Runtime 6.3.2: LLM readiness continuity

Runtime **6.3.2** is published and verified on [GitHub](https://github.com/yeliang-wang/evopilot/releases/tag/v6.3.2), npm and GHCR. Candidate `37177531263`, source `05da3339b32468f3682eea8a1c2b31880a6c38a1`, supplies the unchanged release artifacts. Expert 2.3.0, Harness 4.8.1 and the private independent project extensions 1.0.1 retain their versions.

An unchanged approved workspace LLM binding remains usable after its original preflight becomes older than 15 minutes. The same rule applies to ordinary Goal/Loop model selection and persisted bindings after restart or upgrade from 6.3.1. Users do not need to reenter credentials or repeat preflight solely because time elapsed.

Fresh successful preflight is still required for initial or explicitly replaced bindings. Profile and SecretRef changes, revoked or unavailable credentials, scope and CAS conflicts, failed or mismatched proof, and invalid or future proof times still refuse. Readiness reads do not call the model, refresh evidence, create a new binding or start a timer. Ordinary upstream request failures remain visible; this change does not add continuous provider health monitoring.

Validation covers boundary times, aged binding selection, restart, initial stale-proof refusal and existing failure and scope controls, followed by exact installed Candidate MCP/model verification and full regression. Historical 6.3.1 acceptance remains immutable and is reviewed per affected requirement. The approved Codex-only live Host scope applies; a new 90-minute soak and native credential interaction are omitted and are not counted as passed.

See the [approved Roadmap](../roadmap/ROADMAP.md#runtime632-llm-readiness-continuity) and [readiness guide](../guides/first-run-llm-readiness.md).

Acceptance passed ten new criteria, four current cases, 2,414 exact installed regression tests and individual impact review of 409 immutable inherited criteria. These are distinct from the historical 6.3.1 campaign.
