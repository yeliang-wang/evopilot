# EvoPilot v2.4.1 Release Notes

EvoPilot v2.4.1 is a documentation and CLI consistency release for agent-operated Harness evolution. It keeps the v2.4.0 one-command Harness evolution control-plane behavior intact, then makes the `docs/` operating surface explicit enough for third-party AI agents to simulate a human operator and for humans to follow the same end-to-end scenarios.

## What Changed

- Added `docs/guides/ai-agent-scenarios.md` as the task-oriented scenario matrix between CLI quickstart, automation rules, workflows, command reference, and production runbook.
- Covered owned repositories, writable forks, read-only public repositories, source-project HarnessTemplate evolution, attachment/log/EvoPilot-history template evolution, project profile upgrades, blocker repair, and release verdict inspection.
- Documented AI Agent final report fields for project harness profile version/digest, goal/target/loop IDs, release decision status, LLM provider/model/token usage, request IDs, blockers, and human review state.
- Added explicit stop rules for `nextAction`, human gates, `NO-GO`, `BLOCKED`, `FAILED`, repair, stale project harness profiles, and missing credentials.
- Added `evopilot harness template evolution sources` to CLI help and functional test coverage.
- Added production asset verification for the new AI Agent scenario guide so release checks fail if it is missing or loses the required scenario coverage.
- Updated current CLI install documentation to the v2.4.1 GitHub Release tarball set.

## Control-Plane Boundary

EvoPilot remains the system of record. The CLI and third-party AI agents submit server-governed requests and must not bypass RBAC, tenant/workspace scope, profile review, template evolution review, source-closure gates, phase-plan approval, release policy, audit, or final release decisions.

Harness evolution still follows explicit review boundaries:

```text
source-project or knowledge source -> auto-match/create-or-resume evolution -> REVIEW_REQUIRED -> administrator review -> approve -> publish -> impact
```

## Compatibility

- Compatible Dashboard: `v2.4.0` or later.
- Compatible CLI/client/contracts packages: `2.4.1`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.1/evopilot-contracts-2.4.1.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.1/evopilot-client-2.4.1.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.1/evopilot-cli-2.4.1.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v2.4.1/install.sh | bash -s -- --dir evopilot-stack
```

## Operator Notes

Use `docs/cli/AGENTS.md` as the AI Agent entry point, `docs/cli/quickstart.md` for the shortest safe path, `docs/cli/automation.md` for JSON parsing and stop rules, and `docs/guides/ai-agent-scenarios.md` to select the task-specific end-to-end path before falling back to command reference details.

Public npm registry packages are a separate publication layer. This release remains installable through GitHub Release tarballs until npm publication is separately executed and verified.

## Rollback

Rollback to `v2.4.0` or the previous image digest, then verify `/health`, `/ready`, `harness evolve`, `harness template match`, template evolution create/advance, AI Agent scenario documentation links, project usage endpoints, and release decisions.
