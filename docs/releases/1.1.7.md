# EvoPilot v1.1.7 Release Notes

EvoPilot v1.1.7 adds an explicit GitHub source with GitLab CI bridge mode for connected projects. Existing GitHub-native and GitLab-native loops remain unchanged: GitHub projects can still run GitHub Actions end to end, and GitLab projects can still run GitLab CI end to end.

## What Changed

- Added `sourceMode=external-source` for GitHub source projects that execute CI/Loop delivery through a GitLab CI workflow project.
- Added `bridge.workflowRepository` with GitLab `baseUrl`, `projectId`, `defaultBranch`, and `gitlabRef` support.
- Extended project DevOps readiness with `sourceMode`, `sourceProvider`, `workflowProvider`, and a `bridge-source` check so source credentials and CI credentials are visible as separate gates.
- Required a GitLab `devopsTokenRef` for bridge execution; EvoPilot does not reuse a GitHub source token to trigger GitLab CI.
- Added GitLab bridge delivery variables for source metadata: `SOURCE_PROVIDER`, `SOURCE_REPOSITORY`, `SOURCE_GIT_URL`, `SOURCE_BRANCH`, `SOURCE_DEFAULT_BRANCH`, `UPGRADE_BRANCH`, `COMMIT_SHA`, `PULL_REQUEST_URL`, `WORKFLOW_PROVIDER`, `WORKFLOW_REPOSITORY`, and `DEVOPS_SOURCE_MODE`.
- Added CLI flags for bridge configuration: `--source-mode`, `--workflow-provider`, `--workflow-base-url`, `--workflow-repo`, `--workflow-project-id`, `--workflow-branch`, and `--gitlab-ref`.
- Added functional coverage for GitHub source + GitLab CI bridge delivery execution.

## Compatibility

- Compatible Dashboard: `v1.0.12` or later for the Agent Console bridge controls.
- Compatible CLI/client/contracts packages: `1.1.7`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.7/evopilot-contracts-1.1.7.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.7/evopilot-client-1.1.7.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.7/evopilot-cli-1.1.7.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.7/install.sh | bash -s -- --dir evopilot-stack
```

## Operator Notes

Use bridge mode only when the project source of truth is GitHub and the execution system is a GitLab CI project. The bridge does not make GitLab the source repository, does not copy secrets into Dashboard, and does not weaken project owner review, source credential preflight, DevOps readiness, LLM readiness, or release decision gates.

For bridge projects, `connect-github-account` means the source writeback credential is missing or unresolved. `connect-gitlab-account` means the GitLab CI execution credential is missing or unresolved.
