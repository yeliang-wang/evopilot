# EvoPilot v2.3.0 Release Notes

EvoPilot v2.3.0 adds server-side HarnessTemplate auto-match for source-driven harness evolution. Administrators can point EvoPilot at historical projects, corpora, attachments, logs, or EvoPilot history and let the control plane decide whether to evolve an existing domain template or create a new domain target from a runtime base.

## What Changed

- Added `POST /api/v1/harness/template-matches` for read-only match previews.
- Added `evopilot harness template match ... --json`.
- Added `evopilot harness template evolution create --auto-match ... --json`.
- Persisted match evidence as `evolution.autoMatch` with decision, confidence, base template, target template, target domain, candidates, reasons, source digests, and next action.
- Added top-level HarnessTemplate layer fields: `harnessLayer`, `domain`, `baseRuntimeTemplates`, `compatibleRuntimeProfiles`, and `matchSignals`.
- Relaxed domain-template validation so administrator-published domains beyond database and API gateway can pass the generic domain execution contract while preserving database/gateway-specific checks.
- Added deterministic distributed-cache matching so a Go cache source can create `distributed-cache-harness@0.1.0` from `go-middleware-harness@1.1.0`.

## Control-Plane Boundary

Automatic matching does not generate, approve, or publish a template. It only creates a reviewable match report and initial evolution target:

```text
template match -> evolution create -> advance -> REVIEW_REQUIRED -> approve -> publish -> impact
```

LLM output remains draft-only. Active `ProjectHarnessProfile` records are never silently rewritten.

Harness template versions remain independent control-plane records. After v2.3.0, future database, gateway, cache, scheduler, or other domain harness upgrades do not require an EvoPilot binary release unless extractor, matcher, schema, API, CLI, or Dashboard code changes.

## Compatibility

- Compatible Dashboard: `v2.3.0` for template match preview and auto-match create.
- Compatible CLI/client/contracts packages: `2.3.0`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.3.0/evopilot-contracts-2.3.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.3.0/evopilot-client-2.3.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.3.0/evopilot-cli-2.3.0.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v2.3.0/install.sh | bash -s -- --dir evopilot-stack
```

## Operator Notes

Use `harness template match` when you need to inspect the server-side decision before creating a run. Use `evolution create --auto-match` when the source material should select the existing/new template target automatically. Stop on `nextAction=confirm-template-match-or-override` and create a new run with explicit base/target values if the match is not acceptable.
