# EvoPilot v1.1.5 Release Notes

EvoPilot v1.1.5 is a GA code-modularity evolution release. It keeps the v1.1.4 distribution-closure release path and advances the server and CLI structure from large transitional composition roots toward explicit storage, application, and interface boundaries.

## What Changed

- Split the server control-plane runtime into a thin HTTP composition root for request lifecycle, authentication handoff, logging, route composition, and startup wiring.
- Moved file-backed persistence into `packages/server/src/storage/file-store/` so `FileStore` is no longer defined in the runtime composition root.
- Moved control-plane use-case helpers into `packages/server/src/application/control-plane-services.ts` as a named transitional application boundary.
- Extracted remaining HTTP branches into focused route modules under `packages/server/src/http/routes/`.
- Split the CLI executable entrypoint from command dispatch. `packages/cli/src/index.ts` is now a thin process wrapper, while `packages/cli/src/commands/runtime.ts` remains the HTTP adapter command runtime.
- Tightened `npm run verify:architecture` to guard storage/application/interface ownership, route-prefix extraction, `FileStore` placement, CLI entrypoint thinness, and file-size budgets.
- Updated package versions, shared version fallbacks, installer defaults, OpenAPI metadata, Helm metadata, and release validation pointers to `1.1.5`.

## Compatibility

- Compatible Dashboard: `v1.0.8` or later.
- Compatible CLI/client/contracts packages: `1.1.5`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS immutable rollout.
- Kubernetes: Helm chart path `charts/evopilot`.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.5/evopilot-contracts-1.1.5.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.5/evopilot-client-1.1.5.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.5/evopilot-cli-1.1.5.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.5/install.sh | bash -s -- --dir evopilot-stack
```

Windows PowerShell bootstrap:

```powershell
iwr https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.5/install.ps1 -OutFile install.ps1
.\install.ps1 -Dir evopilot-stack
```

Install the Helm chart from source or the release chart archive:

```bash
helm install evopilot ./charts/evopilot --namespace evopilot --create-namespace
```

## Public npm Boundary

Public npm registry packages are not published in this release layer. The repository includes `.github/workflows/npm-packages.yml` and `npm run verify:npm-registry` for that separate action.

After npm publication, verify the public registry path:

```bash
npm run verify:npm-registry -- --version 1.1.5
```

Only after that command passes should operators use:

```bash
npm install -g @evopilot/cli@1.1.5
npx create-evopilot@1.1.5 self-host --dir evopilot-stack --init-env
```

## Immutable ECS Rollout

Resolve and deploy one release digest:

```bash
npm run ecs:immutable-rollout -- \
  --version 1.1.5 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

Run a rollback and forward drill:

```bash
npm run ecs:immutable-rollout -- \
  --rollback-version 1.1.4 \
  --forward-version 1.1.5 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

## Operator Notes

This release changes source organization, package versions, installer metadata, Helm metadata, OpenAPI metadata, and architecture verification. It does not intentionally change API semantics, CLI stop rules, RBAC, tenant/workspace scope, source-closure gates, release policy, production authentication requirements, or the public npm publication boundary.

For code modularity review, the accepted state is that EvoPilot now has clear storage/application/interface layering plus a sustainable architecture guard. Remaining work is narrower: split the large transitional application helper and CLI command runtime by domain when those areas change next.
