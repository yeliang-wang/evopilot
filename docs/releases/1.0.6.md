# EvoPilot v1.0.6 Release Notes

## Summary

EvoPilot v1.0.6 is a GA package-boundary and loop worker runtime patch. It keeps the v1.0.0 product contract and v1.0.5 immutable deployment path, while making the TypeScript workspace boundaries explicit and verifiable.

## What Changed

- Added `@evopilot/contracts` as the shared source for API, CLI, runtime, version, stop-rule, and package-boundary metadata.
- Added `@evopilot/worker-runtime` as the packaged loop worker runtime.
- Reduced `scripts/loop-worker.mjs` to a thin launcher that delegates to `@evopilot/worker-runtime`.
- Added `npm run verify:architecture` and included it in `npm run check`.
- Updated README, architecture, loop runtime, scripts, release-management, API version, and open-source readiness docs for the new package boundary.

## Who Should Upgrade

Upgrade if you operate EvoPilot workers, validate the repository through `npm run check`, or consume release artifacts that should expose the new package graph and runtime startup path.

## Compatibility

- Compatible Dashboard: v1.0.3 or later.
- API contract version: v1.
- No data migration is required.
- Existing loop worker environment variables are preserved.

## Validation

- `npm run check`
- `npm run release:artifact`
- `npm run verify:release-artifact`
- `git diff --check`

## Deployment Notes

For source-ref deployments, pull the `v1.0.6` source or the corresponding `main` commit, reinstall workspace dependencies, and restart the API and loop worker. The worker entry remains:

```bash
npm run loop-worker
```

For immutable ECS rollout, continue to deploy the image reference recorded in the GitHub Release image metadata:

```bash
export EVOPILOT_IMAGE='ghcr.io/yeliang-wang/evopilot@sha256:<digest>'
docker compose -p evopilot --env-file .env.production -f deploy/ecs/compose.immutable.yaml up -d --no-build
```

Preserve production `.env.production`, data volumes, Postgres backup policy, and server-side credentials. Do not overwrite production secrets from the release archive.

## Rollback

Rollback to `v1.0.5` or the previous image digest, then verify `/health`, `/ready`, worker state, audit events, and release decisions.
