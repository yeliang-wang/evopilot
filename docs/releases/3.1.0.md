# EvoPilot v3.1.0 Release Notes

EvoPilot v3.1.0 adds read-only Harness Registry consumption. Harness lifecycle, evolution, review, approval, versioning, and publication remain owned by `evopilot-harness`; EvoPilot only reads `harness-registry.yaml`, reads enabled Catalog roots, auto-matches a published Harness during planning, and records registry/catalog/template evidence in `plan.selectedHarness`.

## Added

- `EVOPILOT_HARNESS_REGISTRY_CONFIG` startup configuration.
- Read-only Registry projection in `GET /api/v1/harness/catalogs`.
- Registry-derived Catalog mounts with `priority`, `release`, `expectedCatalogDigest`, registry path, and registry digest metadata.
- Auto-match tie breaking by Registry Catalog priority when Harness scores are equal.
- `plan.selectedHarness.registryPath`, `registryDigest`, `registryCatalogPriority`, and `registryCatalogRelease`.
- Source-level cleanup of the remaining EvoPilot-side Harness template production/evolution modules and local template write paths.

## Kept

- EvoPilot still has no `evopilot harness ...` lifecycle CLI.
- EvoPilot still has no Harness template write APIs, evolution APIs, approval APIs, local template store, or Catalog mutation APIs.
- Legacy `EVOPILOT_HARNESS_CATALOG_DIR` and `EVOPILOT_HARNESS_CATALOG_DIRS` remain supported only when no Registry is configured.

## Upgrade

Publish the Registry from `evopilot-harness v1.2.0`:

```bash
evopilot-harness catalog publish --source harnesses --out published --json
evopilot-harness registry publish --catalog published --registry harness-registry.yaml --json
evopilot-harness registry validate --registry harness-registry.yaml --json
```

Start EvoPilot with:

```bash
EVOPILOT_HARNESS_REGISTRY_CONFIG=/opt/evopilot-harness/harness-registry.yaml
```
