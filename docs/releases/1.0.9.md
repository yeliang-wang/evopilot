# EvoPilot v1.0.9 Release Notes

EvoPilot v1.0.9 is a GA distribution-entrypoint hardening patch. It keeps the v1.0.8 npm, self-host, and Helm distribution surface, then adds manifest-verified installers, a Windows PowerShell entrypoint, installer release assets, and Helm render smoke for service exposure.

## What Changed

- Added `installers/manifest.json` to pin the release version, npm package entrypoints, container tags, installer URLs, and installer checksums.
- Hardened `install.sh` with manifest validation, Node.js 22 preflight, `--dry-run`, `--skip-manifest`, and explicit manifest URL/package overrides.
- Added `install.ps1` for Windows PowerShell self-host bootstrap with the same manifest and version checks.
- Added release assets for `install.sh`, `install.ps1`, and `evopilot-<version>-install-manifest.json`.
- Added Helm `service.extraPorts` and `dashboard.service.extraPorts` rendering for platform-specific Service exposure.
- Added Helm template smoke verification for extra API and Dashboard service ports.

## Compatibility

- Compatible Dashboard: `v1.0.7` or later.
- Compatible CLI/client/contracts packages: `1.0.9`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks.
- Kubernetes: Helm chart path `charts/evopilot`.

## Install Paths

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.0.9/install.sh | bash -s -- --dir evopilot-stack
```

Windows PowerShell bootstrap:

```powershell
iwr https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.0.9/install.ps1 -OutFile install.ps1
.\install.ps1 -Dir evopilot-stack
```

Generate with npm directly:

```bash
npx create-evopilot@1.0.9 self-host --dir evopilot-stack --init-env
```

Install the CLI after npm publication:

```bash
npm install -g @evopilot/cli@1.0.9
```

Install the Helm chart from source or the release chart archive:

```bash
helm install evopilot ./charts/evopilot --namespace evopilot --create-namespace
```

## Operator Notes

The tagged installers validate the release manifest before invoking `create-evopilot`. Use `--skip-manifest` only for reviewed offline installs.

The Helm chart still defaults to ClusterIP services. Use `service.extraPorts` or `dashboard.service.extraPorts` only when the target platform requires additional service exposure.

Desktop installer and hosted Cloud trial remain outside the published EvoPilot surface for this release.
