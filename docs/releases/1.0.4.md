# EvoPilot v1.0.4 Release Notes

## Summary

EvoPilot v1.0.4 is a GA artifact-publishing patch. It keeps the v1.0.0 product contract and adds immutable release artifacts for operators who need stronger release provenance than a source checkout plus production build.

## What Changed

- GitHub tag publishing now builds and uploads release artifacts:
  - `evopilot-1.0.4-source.tar.gz`
  - `evopilot-1.0.4-sbom.spdx.json`
  - `evopilot-1.0.4-provenance.json`
  - `evopilot-1.0.4-image-metadata.json`
  - `SHA256SUMS`
- The release workflow publishes the production image to GHCR and records its immutable digest in release metadata.
- `deploy/ecs/compose.immutable.yaml` supports ECS deployment by pinned image digest.
- `npm run release:artifact` and `npm run verify:release-artifact` provide local and CI validation for artifact integrity.

## Who Should Upgrade

Upgrade if production rollout evidence must prove the exact release artifact or image digest used in ECS. Operators who are already on v1.0.3 can keep the same product behavior and move only the deployment source from a Git checkout to an immutable image reference.

## Compatibility

- Compatible Dashboard: v1.0.2 or later.
- API contract version: v1.
- No data migration is required.

## Validation

- `npm run check`
- `npm run release:artifact`
- `npm run verify:release-artifact`
- GitHub Release artifact upload through `.github/workflows/release-artifacts.yml`

## Deployment Notes

For immutable ECS rollout, deploy the image reference recorded in `evopilot-1.0.4-image-metadata.json`:

```bash
export EVOPILOT_IMAGE='ghcr.io/yeliang-wang/evopilot@sha256:<digest>'
docker compose -f deploy/ecs/compose.immutable.yaml up -d
```

Preserve production `.env.production`, data volumes, and Postgres backup policy. Do not overwrite production secrets from the release archive.

`v1.0.5` supersedes this deployment command with explicit compose project and env-file flags for ECS production rollout.

## Rollback

Rollback to the previous image digest or release tag, then verify `/health`, `/ready`, worker state, audit events, and release decisions.
