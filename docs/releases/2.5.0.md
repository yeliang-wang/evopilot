# EvoPilot v2.5.0 Release Notes

EvoPilot v2.5.0 is the external Harness Catalog compatibility release. It separates Harness authoring and publication from the EvoPilot runtime while keeping EvoPilot as the control plane that matches, reviews, executes, audits, and releases projects.

## What Changed

- Adds Published Harness Catalog mounts through `GET/POST /api/v1/harness/catalogs`, `GET /api/v1/harness/catalogs/{catalogId}`, and `POST /api/v1/harness/catalogs/{catalogId}/scan`.
- Adds CLI support for `evopilot harness catalog mount|list|inspect|scan`.
- Reads `CATALOG.md` from a mounted catalog and parses only the fenced `yaml evopilot-harness-catalog` block.
- Loads referenced `template.yaml` or `harness.yaml` files dynamically on use, then exposes Catalog templates beside built-in and persisted templates.
- Extends project harness auto-match with template `matchSignals` so external domain Harnesses such as distributed cache can be selected without an EvoPilot code release.
- Adds generated profile evidence for `templateCatalogRef`, `catalogId`, `catalogDigest`, `catalogEntry`, and `catalogEntryDigest`.
- Updates install metadata, Helm defaults, OpenAPI metadata, Dashboard image defaults, and release-facing docs to `2.5.0`.

## Control-Plane Boundary

`evopilot-harness` owns Harness definition authoring, review, versioning, provenance, and publication of a usable Harness Catalog. EvoPilot owns catalog mount authorization, runtime scanning, template matching, `ProjectHarnessProfile` generation, activation gates, goal loop execution, evidence, audit, and release decisions.

EvoPilot does not need to import every Harness from `evopilot-harness`. It reads the mounted Catalog at use time, accepts growth in Catalog entries, and locks concrete template and Catalog digests when a project profile is generated.

## Compatibility

- Compatible Dashboard: `v2.5.0` or later.
- Compatible `evopilot-harness` Catalogs: `compatibleEvopilot: ">=2.5.0"`.
- Compatible CLI/client/contracts packages: `2.5.0`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.5.0/evopilot-contracts-2.5.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.5.0/evopilot-client-2.5.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.5.0/evopilot-cli-2.5.0.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v2.5.0/install.sh | bash -s -- --dir evopilot-stack
```

Mount a published Harness Catalog:

```bash
evopilot harness catalog mount \
  --source /path/to/evopilot-harness/published \
  --json
```

## Operator Notes

Catalog source paths are server-side paths. A browser Dashboard user can request a Catalog mount through EvoPilot API, but the browser never reads local files. If the Catalog changes, run `evopilot harness catalog scan <catalog-id> --json` or let EvoPilot re-read the active mount when templates are listed or matched.

Public npm registry packages remain a separate publication layer. This release remains installable through GitHub Release tarballs until npm publication is separately executed and verified.

## Rollback

Rollback to `v2.4.2` or the previous image digest, then verify `/health`, `/ready`, `harness evolve`, `harness template match`, project harness profile generation, release decisions, and Dashboard `v2.5.0` compatibility if Dashboard remains deployed.
