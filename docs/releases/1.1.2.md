# EvoPilot v1.1.2 Release Notes

EvoPilot v1.1.2 is a GA release-operations evolution release. It keeps the v1.1.1 code-structure boundary work and adds an operator-safe immutable ECS rollout runbook that resolves GitHub Release image metadata before deploying a pinned GHCR digest.

## What Changed

- Added `scripts/immutable-rollback-runbook.mjs` to resolve `evopilot-<version>-image-metadata.json` from GitHub Releases and validate schema, project, version, tag, digest, and immutable image reference.
- Added `npm run ecs:immutable-rollout` for planned deployments, applied ECS rollouts, and rollback/forward drills.
- The rollout script deploys with `deploy/ecs/compose.immutable.yaml`, `docker pull --platform`, and `docker compose ... up -d --no-build --no-deps`, so production uses the published image digest instead of rebuilding from a mutable checkout.
- Applied rollouts verify `/health`, `/ready`, Dashboard HTTP smoke unless skipped, running container state, and container image RepoDigests.
- Extended `npm run release:ready` and `npm run verify:production-assets` so the immutable rollout runbook, evidence schema, and no-build behavior are release-gated.

## Compatibility

- Compatible Dashboard: `v1.0.8` or later.
- Compatible CLI/client/contracts packages: `1.1.2`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS immutable rollout.
- Kubernetes: Helm chart path `charts/evopilot`.

## Install Paths

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.2/install.sh | bash -s -- --dir evopilot-stack
```

Windows PowerShell bootstrap:

```powershell
iwr https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.2/install.ps1 -OutFile install.ps1
.\install.ps1 -Dir evopilot-stack
```

Generate with npm directly:

```bash
npx create-evopilot@1.1.2 self-host --dir evopilot-stack --init-env
```

Install the CLI after npm publication:

```bash
npm install -g @evopilot/cli@1.1.2
```

Install the Helm chart from source or the release chart archive:

```bash
helm install evopilot ./charts/evopilot --namespace evopilot --create-namespace
```

## Immutable ECS Rollout

Resolve and deploy one release digest:

```bash
npm run ecs:immutable-rollout -- \
  --version 1.1.2 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

Run a rollback and forward drill:

```bash
npm run ecs:immutable-rollout -- \
  --rollback-version 1.1.1 \
  --forward-version 1.1.2 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

## Operator Notes

This release changes release operations, package versions, release metadata, and operator documentation. It does not intentionally change API behavior, CLI stop rules, RBAC, tenant/workspace scope, source-closure gates, release policy, or production authentication requirements.

`scripts/immutable-rollback-runbook.mjs` is safe by default. Without `--apply`, it only resolves release metadata and prints planned immutable image references. With `--apply`, it changes ECS container state through SSH and must be run only after the exact GitHub Release assets and CI have closed successfully.

## Rollback

Rollback to `v1.1.1` or the previous image digest with `npm run ecs:immutable-rollout -- --version 1.1.1 --host <ecs-host> --apply --json`, then verify `/health`, `/ready`, Dashboard HTTP smoke, worker state, audit events, container RepoDigests, and release decisions.
