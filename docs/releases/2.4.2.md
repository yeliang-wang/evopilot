# EvoPilot v2.4.2 Release Notes

EvoPilot v2.4.2 closes the release-readiness gap found during the v2.4.1 rollout and hardens immutable ECS deployment for Podman-backed production hosts. It keeps the v2.4.1 AI Agent scenario documentation and CLI consistency work, then makes the release gate and ECS rollout path reproducible from the tracked CLI.

## What Changed

- Added missing `CHANGELOG.md` coverage for the v2.4.1 agent-operated Harness evolution documentation release so `npm run release:ready` can pass on the release commit.
- Updated `scripts/immutable-rollback-runbook.mjs` to resolve GitHub Release image metadata, record the original `tag@sha256` immutable evidence, and deploy with digest-only `repository@sha256` image references.
- Removed the problematic `docker pull --platform <platform> <tag>@sha256:<digest>` remote command from the generated ECS script path. The `--platform` CLI option remains accepted for compatibility, but the production pull uses the digest-only reference that Podman can resolve reliably.
- Updated package versions, installer defaults, OpenAPI metadata, Helm metadata, current distribution docs, and open-source governance checks to `2.4.2`.

## Control-Plane Boundary

EvoPilot remains the system of record. The CLI and third-party AI agents submit server-governed requests and must not bypass RBAC, tenant/workspace scope, profile review, template evolution review, source-closure gates, phase-plan approval, release policy, audit, or final release decisions.

The Harness evolution operating model remains unchanged:

```text
source-project or knowledge source -> auto-match/create-or-resume evolution -> REVIEW_REQUIRED -> administrator review -> approve -> publish -> impact
```

## Compatibility

- Compatible Dashboard: `v2.4.0` or later.
- Compatible CLI/client/contracts packages: `2.4.2`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.2/evopilot-contracts-2.4.2.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.2/evopilot-client-2.4.2.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.4.2/evopilot-cli-2.4.2.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v2.4.2/install.sh | bash -s -- --dir evopilot-stack
```

## Operator Notes

Use `npm run ecs:immutable-rollout -- --version 2.4.2 --host <ecs-host> --apply --json` for the tracked ECS path. The script verifies release metadata from GitHub, deploys the pinned digest without a production rebuild, checks `/health`, `/ready`, Dashboard HTTP, and records container image digest evidence.

Public npm registry packages are a separate publication layer. This release remains installable through GitHub Release tarballs until npm publication is separately executed and verified.

## Rollback

Rollback to `v2.4.1`, `v2.4.0`, or the previous image digest, then verify `/health`, `/ready`, `harness evolve`, `harness template match`, template evolution create/advance, AI Agent scenario documentation links, project usage endpoints, and release decisions.
