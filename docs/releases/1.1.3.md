# EvoPilot v1.1.3 Release Notes

EvoPilot v1.1.3 is a GA code-structure and distribution-verification evolution release. It keeps the v1.1.2 immutable ECS rollout automation and extracts release target runtime logic from the transitional control-plane runtime while adding post-publish public npm registry verification.

## What Changed

- Extracted release target defaults, ProofOps target planning, release scenario matrix handling, evidence summaries, active soak checks, release risk deduplication, and artifact type inference into `packages/server/src/runtime/release-targets.ts`.
- Kept `packages/server/src/runtime/control-plane-runtime.ts` as the transitional HTTP control-plane composition root while reducing its direct release target ownership.
- Updated shared package-boundary metadata and `npm run verify:architecture` so the control-plane runtime must delegate release target helpers and remain under the updated line-count guard.
- Added `scripts/verify-npm-registry-publication.mjs` and `npm run verify:npm-registry` to verify exact-version public npm metadata, empty-project installs, and binary help output after npm publication.
- Extended the npm package publication workflow so release-tag npm publishing is followed by public registry install verification.

## Compatibility

- Compatible Dashboard: `v1.0.8` or later.
- Compatible CLI/client/contracts packages: `1.1.3`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS immutable rollout.
- Kubernetes: Helm chart path `charts/evopilot`.

## Install Paths

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.3/install.sh | bash -s -- --dir evopilot-stack
```

Windows PowerShell bootstrap:

```powershell
iwr https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.3/install.ps1 -OutFile install.ps1
.\install.ps1 -Dir evopilot-stack
```

Generate with npm directly after npm publication:

```bash
npx create-evopilot@1.1.3 self-host --dir evopilot-stack --init-env
```

Install the CLI after npm publication:

```bash
npm install -g @evopilot/cli@1.1.3
```

Install the Helm chart from source or the release chart archive:

```bash
helm install evopilot ./charts/evopilot --namespace evopilot --create-namespace
```

## Public npm Verification

After the release-tag npm workflow completes, verify the public registry path:

```bash
npm run verify:npm-registry -- --version 1.1.3
```

The verification checks `@evopilot/contracts`, `@evopilot/client`, `@evopilot/cli`, and `create-evopilot`, then installs the exact versions into an empty temporary project and verifies the `evopilot` and `create-evopilot` binaries expose help output.

## Immutable ECS Rollout

Resolve and deploy one release digest:

```bash
npm run ecs:immutable-rollout -- \
  --version 1.1.3 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

Run a rollback and forward drill:

```bash
npm run ecs:immutable-rollout -- \
  --rollback-version 1.1.2 \
  --forward-version 1.1.3 \
  --host root@8.153.72.80 \
  --apply \
  --json
```

## Operator Notes

This release changes source organization, package versions, release metadata, npm registry verification, architecture docs, and release workflow checks. It does not intentionally change API behavior, CLI stop rules, RBAC, tenant/workspace scope, source-closure gates, release policy, production authentication requirements, or the v1.1.2 immutable ECS deployment contract.

`packages/server/src/runtime/control-plane-runtime.ts` remains a transitional composition root. The next structural target is extracting remaining release and route application handlers into smaller runtime application modules.
