# EvoPilot v1.1.8 Release Notes

EvoPilot v1.1.8 adds server-governed LLM profile registration, tenant/workspace-safe profile visibility, project default LLM binding, and per-run user profile overrides. Existing GitHub-native, GitLab-native, and GitHub source + GitLab CI bridge loops remain unchanged.

## What Changed

- Added `workspace` and `user` LLM profile scopes.
- Added provider presets for `glm`, `kimi`, `gemma`, and `custom` OpenAI-compatible providers.
- Kept raw LLM secrets server-side through secret refs; CLI and Dashboard submit profile IDs and secret references, not raw API keys.
- Restricted workspace profile creation, testing, and project default binding to workspace administrators.
- Restricted user profiles to the owning actor and allowed them only as per-run overrides, not as project defaults.
- Required project default LLM profiles to be READY workspace profiles.
- Extended LLM preflight and project LLM resolution so loops record the actual provider, model, profile, request ID, and token totals through EvoPilot evidence.
- Added CLI support for profile scope and provider preset registration while keeping `--llm-profile` as the run-time profile selection input.

## Compatibility

- Compatible Dashboard: `v1.0.13` or later for LLM Profiles management and Agent Console binding controls.
- Compatible CLI/client/contracts packages: `1.1.8`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.8/evopilot-contracts-1.1.8.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.8/evopilot-client-1.1.8.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.8/evopilot-cli-1.1.8.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.8/install.sh | bash -s -- --dir evopilot-stack
```

## Operator Notes

Use workspace profiles for project defaults and shared production execution. Use user profiles for a single actor's loop run override. A user profile cannot become the project default because other users in the workspace must not inherit a private LLM account or key reference.

When reporting automation results, include the resolved LLM provider, model, profile ID, token totals, and request IDs from EvoPilot evidence. Dashboard should display these server projections rather than calculating usage in the browser.
