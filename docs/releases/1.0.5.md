# EvoPilot v1.0.5 Release Notes

## Summary

EvoPilot v1.0.5 is a GA immutable-deployment patch. It keeps the v1.0.0 product contract and the v1.0.4 artifact chain, then hardens the ECS compose template for pinned image-digest rollout.

## What Changed

- `deploy/ecs/compose.immutable.yaml` now declares the `evopilot` compose project name so operators do not accidentally create an `ecs` project when running the template from `deploy/ecs/`.
- The immutable compose template resolves the production env file from the repository root by default.
- Release and operations docs use explicit `-p evopilot`, `--env-file .env.production`, and `--no-build` commands for image-digest deployment.
- Runtime product version evidence is aligned to `1.0.5`.

## Who Should Upgrade

Upgrade if production rollout evidence must prove that ECS is running the exact GitHub Release image digest with the intended compose project, volumes, env file, and service names.

## Compatibility

- Compatible Dashboard: v1.0.3 or later.
- API contract version: v1.
- No data migration is required.

## Validation

- `npm run check`
- `npm run release:artifact`
- `npm run verify:release-artifact`
- GitHub Release artifact upload through `.github/workflows/release-artifacts.yml`

## Deployment Notes

For immutable ECS rollout, deploy the image reference recorded in `evopilot-1.0.5-image-metadata.json`:

```bash
export EVOPILOT_IMAGE='ghcr.io/yeliang-wang/evopilot@sha256:<digest>'
docker compose -p evopilot --env-file .env.production -f deploy/ecs/compose.immutable.yaml up -d --no-build
```

Preserve production `.env.production`, data volumes, and Postgres backup policy. Do not overwrite production secrets from the release archive.

## Rollback

Rollback to the previous image digest or release tag, then verify `/health`, `/ready`, worker state, audit events, and release decisions.
