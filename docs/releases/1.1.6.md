# EvoPilot v1.1.6 Release Notes

EvoPilot v1.1.6 is a GA project LLM usage visibility patch. It keeps the v1.1.5 control-plane boundary work and makes EvoPilot the system of record for connected-project token consumption, actual LLM provider/model usage, latest loop token evidence, and Dashboard-ready workspace rollups.

## What Changed

- Added `GET /api/v1/projects/{projectId}/usage` for one connected project's LLM usage projection.
- Extended `GET /api/v1/workspaces/{workspaceId}/usage` with workspace `llmUsage`, `projectsWithLlmUsage`, `loopsWithLlmUsage`, `topProject`, and `projectUsage[]`.
- Added `providerModelUsage[]` rows grouped by `projectId + provider + model + profileId` so one project can show multiple actual LLM combinations over time.
- Exposed calls, input tokens, output tokens, total tokens, credits, cost, latest loop id/status/token total, and request id from server-side Loop trace evidence.
- Preserved configured LLM binding (`configuredLlm`) separately from actual observed provider/model usage.
- Updated OpenAPI and Dashboard integration docs so Dashboard displays EvoPilot projections and does not calculate project or workspace token totals in browser code.
- Updated package versions, shared version fallbacks, installer defaults, OpenAPI metadata, Helm metadata, Dashboard image defaults, and release validation pointers to `1.1.6`.

## Compatibility

- Compatible Dashboard: `v1.0.9` or later.
- Compatible CLI/client/contracts packages: `1.1.6`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS immutable rollout.
- Kubernetes: Helm chart path `charts/evopilot`.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.6/evopilot-contracts-1.1.6.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.6/evopilot-client-1.1.6.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v1.1.6/evopilot-cli-1.1.6.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.6/install.sh | bash -s -- --dir evopilot-stack
```

Windows PowerShell bootstrap:

```powershell
iwr https://raw.githubusercontent.com/yeliang-wang/evopilot/v1.1.6/install.ps1 -OutFile install.ps1
.\install.ps1 -Dir evopilot-stack
```

Install the Helm chart from source or the release chart archive:

```bash
helm install evopilot ./charts/evopilot --namespace evopilot --create-namespace
```

## Public npm Boundary

Public npm registry packages are not published in this release layer. The repository includes `.github/workflows/npm-packages.yml` and `npm run verify:npm-registry` for that separate action.

After npm publication, verify the public registry path:

```bash
npm run verify:npm-registry -- --version 1.1.6
```

Only after that command passes should operators use:

```bash
npm install -g @evopilot/cli@1.1.6
npx create-evopilot@1.1.6 self-host --dir evopilot-stack --init-env
```

## Operator Notes

LLM usage in this release is project and Loop evidence, not an LLMOps quota-window view. It does not introduce fixed reset periods. Dashboard and other clients should show the server-projected `projectUsage[].providerModelUsage[]` rows and preserve `latestLoopId`, `latestLoopStatus`, `latestLoopTotalTokens`, and `requestId` for troubleshooting.

When `llmUsage.provider` or `llmUsage.model` is `mixed`, read `providerModelUsage[]` for the actual provider/model/profile rows used by that project.
