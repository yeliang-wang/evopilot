# EvoPilot v2.0.0 Release Notes

EvoPilot v2.0.0 upgrades HarnessTemplate from mostly language/runtime baselines to a domain-first model for vertical product evolution. Existing project, DevOps, LLM profile, loop, evidence, and release decision flows remain compatible.

## What Changed

- Added `database-product-harness@2.0.0` for self-developed database products.
- Added `api-gateway-harness@2.0.0` for gateway, ingress, traffic proxy, and service-mesh gateway products.
- Added `enterprise-management-software-harness@2.0.0` for CRM, ERP, workflow, and enterprise management products.
- Generated `ProjectHarnessProfile` records now carry template layer metadata such as `harnessLayer`, `domain`, `compatibilityProfiles`, `architectureProfiles`, `runtimeProfiles`, and `referenceBoundary`.
- Automatic template matching gives strong vertical domain signals priority, then uses runtime language signals as the implementation layer.
- Public template packs under `harness-templates/public/` now include the three v2 domain templates.

## Compatibility

- Compatible Dashboard: `v2.0.0` for domain-template display and v2 release notes.
- Compatible CLI/client/contracts packages: `2.0.0`.
- API contract version: `v1`.
- Node.js: 22 or later.
- Docker Compose: v2 for generated self-host stacks and ECS rollout.

## Database Product Boundary

The database harness evolves the owner's database product. PostgreSQL, MySQL, SQLite, CockroachDB, TiDB, and similar systems are reference sources only: compatibility corpora, SQL dialect examples, protocol references, or differential oracles. They are not the default product being evolved.

## Install Paths

Install the CLI from the GitHub Release tarball set:

```bash
npm install -g \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.0.0/evopilot-contracts-2.0.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.0.0/evopilot-client-2.0.0.tgz \
  https://github.com/yeliang-wang/evopilot/releases/download/v2.0.0/evopilot-cli-2.0.0.tgz
```

Self-host bootstrap from the release tag:

```bash
curl -fsSL https://raw.githubusercontent.com/yeliang-wang/evopilot/v2.0.0/install.sh | bash -s -- --dir evopilot-stack
```

## Public npm Boundary

Public npm registry packages are a separate publication layer. After npm publication, verify the registry path:

```bash
npm run verify:npm-registry -- --version 2.0.0
```

## Operator Notes

Normal project onboarding still uses automatic template matching. `--from-template` remains an administrator or advanced override. Template publication and HarnessTemplateEvolution still require administrator review, validation, diff, source coverage, impact reporting, and explicit approval.

Existing active `ProjectHarnessProfile` records are not silently rewritten. Projects that should move from a runtime/language template to a new domain template need a reviewed DRAFT profile and explicit activation.

## Rollback

Rollback to `v1.1.8` or the previous image digest, then verify `/health`, `/ready`, project harness template listing, profile generation, Dashboard compatibility, project usage endpoints, and release decisions.
