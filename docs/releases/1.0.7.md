# EvoPilot v1.0.7 Release Notes

## Summary

EvoPilot v1.0.7 is a GA test-matrix and release-readiness patch. It keeps the v1.0.0 product contract and v1.0.6 package-boundary runtime, then adds stronger failure recovery, PR artifact, and release readiness evidence before production rollout.

## What Changed

- Added `npm run test:failure-recovery` with a JSON matrix at `dist/test-matrix/failure-recovery-matrix.json`.
- Added `npm run release:ready` with a JSON readiness report at `dist/test-matrix/release-ready.json`.
- Added control-plane failure recovery coverage for auth rejection, source credential blockers, DevOps blockers, explicit LLM profile blockers, and source closure repair actions.
- Added loop-worker retry and fallback API URL coverage to the failure recovery matrix.
- Added GitHub Actions workflows for failure recovery, release readiness, and PR readiness artifacts.
- Added the operations test matrix documentation and routed testing and release-management docs to the new gates.

## Who Should Upgrade

Upgrade if you maintain EvoPilot releases, review release-impacting PRs, or deploy to ECS production and need failure recovery evidence, release readiness evidence, and review artifacts before rollout.

## Compatibility

- Compatible Dashboard: v1.0.4 or later.
- API contract version: v1.
- No data migration is required.
- Existing runtime, worker, source credential, LLM profile, and release decision configuration is preserved.

## Validation

- `npm run check`
- `npm run test:failure-recovery`
- `npm run release:ready`
- `npm run release:artifact`
- `npm run verify:release-artifact`
- `git diff --check`

## Deployment Notes

For immutable ECS rollout, deploy the image reference recorded in `evopilot-1.0.7-image-metadata.json`:

```bash
export EVOPILOT_IMAGE='ghcr.io/yeliang-wang/evopilot@sha256:<digest>'
docker compose -p evopilot --env-file .env.production -f deploy/ecs/compose.immutable.yaml up -d --no-build
```

Preserve production `.env.production`, data volumes, Postgres backup policy, and server-side credentials. Do not overwrite production secrets from the release archive.

## Rollback

Rollback to `v1.0.6` or the previous image digest, then verify `/health`, `/ready`, worker state, audit events, failure recovery evidence, and release decisions.
