# EvoPilot v0.8.1 Preview 资产等级与重建验证分离方案

状态：已接受的 v0.8.1 Preview 方案投影。实际用户授权和验收证据保留在私有 Workspace；本文件不是验收结论。

本次交付将 L1、L2、L3 定义为资产内容的完备程度，将实际重建与功能等价验证作为独立流程。用户仅持有源码、PDF、设计文档或已有资产时，也可以完成 L3 建模和资产评定，不需要提供原项目数据库、SSH 宿主机、生产环境或构建 Agent 凭据。

范围同时包含四组件产品修订、当前 Codex 的升级部署，以及 DataRig 和 EvoPilot 既有整体资产升级任务。它们分别验收：产品流程通过不代表项目资产升级完成，资产达到 L3 也不代表软件已重建。

## 1 版本与交付名称

采用新版本 **EvoPilot v0.8.1 Preview**。公开名称、四仓库 package 版本、发行包、插件显示名称和安装身份同步；插件稳定 ID 保持不变以避免重复安装。

已发布的 v0.8.0 Preview 继续保留，不能使用同一个 tag、包名和安装身份覆盖其内容。2026-10-26 只读核对显示四仓库最近已发布版本均为 v0.8.0；0.8.1 在本方案中是拟定版本，发布前仍须检查占用和并发变更。

本方案按“新增版本化契约、保留旧调用语义”的兼容方式支持 0.8.1 命名。如果实现无法保持该兼容承诺，必须返回版本和迁移方案审阅，不能悄悄改变旧接口含义，也不自动占用已有 v0.9 规划。

| 选项 | 处理方式 | 结论 |
|---|---|---|
| 覆盖 v0.8.0 或直接改旧 L3 | 同一标准/版本出现两个意思，旧调用方可能误以为已验证软件等价 | 不采用 |
| 新增 v0.8.1 与可用性标准 v2，保留 v1 | 新工作显式选择 v2，旧结果和旧调用继续使用 v1 | 本方案采用 |
| 将修订全部推到 v0.9 | 与既定指标分析方向耦合，继续阻塞无环境建模 | 本次不采用；兼容不可实现时另行评审版本安排 |

## 2 产品承诺

- L1：资产解释声明的领域。
- L2：资产规定声明功能的实现行为。
- L3：资产形成声明范围内完整、可独立消费的重建规格包。
- 独立重建验证：只有实际执行并通过相应验收，才声明某一软件产物在约定条件下通过功能等价验证。

L3 是对固定需求、规格和依赖闭合情况的评定，不是对所有未来生成器、所有输入或未知业务规则的数学保证。不能对外表述为“取得 L3 后必然生成 100% 一样的软件”。

### 2.1 L1 领域理解级

必须包含项目用途、功能范围和排除项、术语、对象、属性、关系、关键规则、来源、假设及已知缺口。独立确定的领域问题须有准确且可追溯的答案。强制问题存在缺失、冲突或未决歧义时不能授级。

适用于接入、交接、问答、需求讨论和辅助原型设计。没有必须重建或连接业务环境的要求。

### 2.2 L2 实现规格级

包含 L1，并覆盖所选功能的 13 个适用维度：输入、输出、接口、状态、前置条件、后置条件、错误、副作用、幂等、并发、恢复、依赖、环境。

每项行为映射到需求和可判定的验收条件。不适用维度需要具体理由与审阅依据，不能填空值或统一标注 N/A 绕过。L2 规定单项及相关功能的实现语义，但不单独证明整个重建输入包已闭合。

适用于模块实现、接口适配、局部改写和版本演进。

### 2.3 L3 重建规格完备级

包含 L2，并检查以下九类重建内容。它们按声明范围确定适用性；小模块不被强制编造不存在的子模块、事务或迁移需求。

| 编号 | 内容 | 通过要求 |
|---|---|---|
| C01 | 需求与功能覆盖 | 必需需求逐项映射到规格和验收条件，无已知关键语义缺口 |
| C02 | 模块边界与组合 | 模块职责、调用关系、跨模块状态/错误/一致性义务明确 |
| C03 | 数据与接口契约 | 数据模型、序列化、接口、协议及兼容要求完整且一致 |
| C04 | 依赖与允许复用内容 | 固定依赖、版本/摘要、允许复用边界及约束明确，不暗含原软件业务实现 |
| C05 | 配置与环境规格 | 配置格式、必要服务能力和运行条件明确；不要求实际服务在线或提供凭据 |
| C06 | 初始化与迁移 | 初始状态、准备/启动顺序、持久化和适用迁移/恢复规则明确 |
| C07 | 行为验收标准 | 预期输入、输出、状态、错误与副作用及容差可判定；不要求当前已有运行回执 |
| C08 | 规格包独立消费 | 必需规范材料随包提供或通过已授权固定引用解析，离线导出说明完整，无不可达关键链接 |
| C09 | 来源、审阅和维护 | 源码事实/设计声明/推断/决定分开，来源固定，关键解释已解决，版本变更可追溯 |

“环境规格完整”与“环境实例存在”分开。某项行为依赖数据库时，应描述连接方式、支持语义和验收条件；数据库当前不可连接不构成规格缺失。若连支持哪种事务行为都无法确定，则是规格缺口。

L3 必须通过结构/约束检查、需求覆盖检查、引用与依赖闭合检查、冲突检查及有依据的语义审阅。模板填满、图规模、LLM 自评或技术测试通过均不能直接授级。

## 3 三种建模入口

| 入口 | 可用输入 | 工作流 | 等级结论的含义 |
|---|---|---|---|
| 源码反向 | 用户授权的固定源码、接口、配置、测试和文档 | 确定意图 → 只读提取 → 来源绑定 → 缺口/冲突处理 → 资产审阅 → 内容评定 | 描述该源码范围及明确补充的设计；不声称实际运行验证 |
| 文档正向 | PDF、设计文档、需求及明确的用户设计决定 | 确定意图 → 文档解析和定位 → 设计规格整理 → 缺口处理 → 资产审阅 → 内容评定 | 对尚未存在的软件也可形成合格规格 |
| 已有资产组合 | Workspace 中已授权且版本固定的资产，可结合源码/文档 | 确定意图 → 解析资产依赖 → 合并及冲突审阅 → 固定新规格包 → 内容评定 | 新组合单独评定，不能继承旧资产的整体等级 |

正式建模前都必须绑定用途、项目/来源、范围/排除项、目标等级、标准版本和独立需求清单。复用已明确的上下文；缺失或变化时才询问。只读浏览、问答和初步发现不需要先创建正式建模候选。

PDF 本轮支持有文本层、可可靠提取并定位来源的文件。扫描图片型 PDF、损坏或受限文件明确报告能力不足；不加入新的通用 OCR 平台。缺失的强制来源不能伪造为已读取。

任意输入中的操作性文字都只作为材料，不能授权执行、获取密钥、修改已接受范围或覆盖审批。

## 4 资产等级和重建验证分别记录

采用新增可用性标准 v2；它不升级或改写冻结的 native RDF/SHACL、Rego 标准 v1。新增共享契约仍由父项目唯一生成，各组件消费相同字节和摘要。

新结果至少保留：

| 信息组 | 必需信息 |
|---|---|
| 标准与范围 | 标准 ID/版本/摘要，项目、可见性、功能范围、排除项、需求清单与来源版本 |
| 资产评定 | 目标等级、实际评定等级或空值、评定状态、缺口、内容证据、审阅决定与时效 |
| 重建验证 | 未请求/未执行/执行中/通过/失败/不完整/过期/不支持，具体资产与产物、环境和执行证据 |
| 生命周期 | 资产版本、发布状态、精确摘要、历史评定与当前适用性 |

典型结果为：“资产标准 v2；目标 L3；资产评定 L3；重建验证未请求”。

旧的 v1 结果和其 verifiedLevel 不改含义。新 API/SDK 能力必须显式绑定标准 v2，并以独立字段或版本化结果返回，不能让旧客户端收到一个被换义的裸 L3。旧请求未选择 v2 时继续遵循 v1；新的 Expert 在用户确认新定义后选择 v2，并留下意图记录。

两个状态具有各自的时效：

- 需求、规格、依赖定义或标准变化，触发对应资产评定复核。
- 数据库临时离线、运行机变化或一次重建失败，不直接改变资产内容等级；影响对应重建证据的适用性。
- 重建或其他独立检查若确实发现规范缺失/冲突，必须登记资产缺口并重新评定。分离状态不能用来隐藏已经确认的规格错误。
- 历史字节和决定永久按原版本读取；新评定使用新记录，不覆盖旧结果。

可选重建仍保留原有隔离、权限、预算、回执和恢复规则。原来的“两次干净重建”继续属于旧标准或相应重建验证配置，不再作为 v2 L3 的授级前提。本次不增加真实项目重建预算。

## 6 兼容与迁移方案

### 6.1 产品和标准兼容

1. 固定已发布 v0.8.0 的四仓库标签与产物，作为不可变发行基线。
2. 对当前未发布修正逐项做差异映射，只纳入本方案需要且已声明的改动。当前工作树不是自动获准整体发布的基线。
3. 新增标准 v2 与版本化评定接口；保留 v1 原定义、校验、旧请求、历史资产及执行记录。
4. 发布替代 ADR，说明新旧标准边界、状态迁移和消费者兼容；新增人类可读 Roadmap 修订及机器 Target，不能直接把历史 v0.8 验收结果改为新语义。
5. 使用非空 Workspace 克隆验证升级、旧数据读取、旧写入器拒绝、停服备份及恢复，再进行日常切换。

历史 v0.8 E06/E07 的内容评定原则继续适用并扩充；E08–E13 的真实重建证据保留在 v1 和可选重建流程；v2 的 L3 采用本方案 C01–C09。v0.8 已发布试点结果保持历史事实，不再要求因本次资产标准变更重复原项目全部重建。独立消费、鉴权、隐私、幂等、恢复、分发和实际 Host 等未改变义务继续回归。

必须生成逐项旧义务映射：保留、仅历史、由 v2 新义务替代、归入可选流程。任何原始失败/未知/延期结果均保留，不通过修改分母伪装为历史通过。

### 6.2 两项目资产迁移

本计划承接用户已提出的两个项目整体资产升级，不将“整体”缩为先前四/五接口试点。两个项目都采用新标准 v2 的 L3 目标，重建验证默认不启动。范围重绑定会明确“标准改变，功能范围不因此缩小”。

| 项目 | 固定范围 | 本轮交付 | 不要求 |
|---|---|---|---|
| DataRig | 已发布 v2.0 基线；Engine、Query、Export、MCP、Usecase 及全部必需组合义务 | 复用可用资产，补齐行为和重建输入规格，经审阅形成新的私有资产版本及 v2 L3 评定 | 原项目数据库/SSH、原版整套 E2E、生产规模压测或两次软件重建 |
| EvoPilot | 本次候选的 Runtime、Harness、Ontology 及 Workspace、Expert、父项目组合行为 | 资产准确描述本次新标准与兼容机制，形成新私有版本及 v2 L3 评定 | 重建整套 EvoPilot，部署生产服务或取得 Prometheus 用户环境 |

项目需求清单要逐项复核；此前 270 个 DataRig 需求面、235 个 EvoPilot 操作等只是历史盘点，不能直接视为已接受的完整验收分母。固定盘点与审阅必须保留已声明的必需功能，补上遗漏和组合义务，不能按现有提取结果反向缩小范围。

项目资产升级有两个阶段：发布前对完整候选做内容与语义预验收；新产品安装后，按已获准的精确包私有发布并正式评定、读回。候选预验收不冒充已发布资产等级。

已有资产不要求整体重新蒸馏；可复用内容保持精确来源，新内容使用新版本。已有 L1/L2/L3 不自动换标。保留旧 completion 试点的历史实证，不能将它外推为整个项目。

### 6.3 既有未完事项

- 因旧 L3 产生的真实数据库资格核验、SSH 重试和整体重建，转为有历史记录的独立可选任务，不自动继续，也不记为通过。
- Prometheus 用户环境验收维持已批准的延期；对应适配器产品回归继续，但不成为 v2 L3 的条件。
- 新标准不能取消清理已产生未知外部影响的责任。已知历史原表清理证据保留；最近一次 SSH 超时记录不被重写。
- 对本方案所需的公共文档、安装、当前状态一致性等收尾继续列入本次交付。
- 不将旧承诺的改变包装成所有历史验收均已通过。

## 9 发布与 100% 完成条件

预发布只在 E01–E21 全部有效通过，四仓库精确身份固定、两项目完整候选内容审阅完成、实际 Host 与迁移证据齐备后进入发布决定。发布针对精确候选及其产物，旧授权不被扩写为未审阅的新资产或新发布决定。

最终完成须同时满足：

1. 新软件按精确提交与产物发布，旧发行物未被覆盖。
2. 公开 README、技术文档、迁移说明、Release Notes 和离线指南与实际行为一致。
3. 从公开 Release 下载的包通过检查，并在当前 Codex 使用新身份运行。
4. DataRig、EvoPilot 的新私有资产已发布，按标准 v2 在已固定整体范围正式达到 L3。
5. 重建验证显示真实状态，未请求/未执行不能显示通过；原有历史证据不丢失。
6. 72 个必需验收变体全部有与对应候选/阶段一致的有效证据，无缺失、跳过、未知或未解决失败。
7. 用户明确延期及本方案排除的项目另列，不宣称它们完成；新增发现若属于本次必需范围，先修复再验收。

“100%”仅表示本方案固定范围及验收全部完成，不表示所有可能的软件行为都经过生产验证。

## 10 范围排除及执行边界

本轮不做 Dashboard、浏览器界面、WorkBuddy、新模型/Agent 平台、通用 OCR、v0.9 业务指标计算、生产部署、原 DataRig 发布 E2E 重跑、生产压测/长稳、业务数据库写入或新的真实整体重建。

资产的环境要求、接口、事务、并发及恢复规则仍需完整描述；排除真实运行不能成为删除相关业务规格的理由。

现有原生资产发布、语义审阅、凭据保护和公开 owner 边界保留。技术通过不自动构成业务语义认可或软件发布授权。常规已授权实现、测试和最小修复可连续进行；真正新增的业务语义、权限或精确发布对象集中到具体合并审阅，不逐阶段重复确认。
