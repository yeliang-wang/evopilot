# 首次使用 EvoPilot

[English](../first-journey.md) | 简体中文 · [中文目录](README.md)

适用 v0.8.3 Preview。前提是完成[安装与实际连接核验](installation.md)。目标是在你指定的范围内生成可审阅资产，并能区分草稿、发布、内容等级和实际执行结果。

## 1. 初始化与激活

在 Codex 中选择 EvoPilot 插件并提出：

> 开始使用 EvoPilot，初始化我的个人 Workspace，展示正向与反向示例。

Expert 先检查绑定；未绑定时说明默认可编辑项目目录 `~/evopilot-workspace` 和受保护状态目录 `~/.local/share/evopilot/workspaces/<workspace-id>`，再初始化并激活当前会话。你可以指定自己的目录，无需 GitHub 登录或单独建仓。已有占用目录不会被覆盖。仅询问能力或读取指南保持被动。

项目目录包含文档、合成示例、公开复用资产和私有项目材料。`public` 表示复用范围，不是上传授权。数据库、控制状态、凭据和原始执行证据应在 Git 之外。恢复需要完整 Workspace 备份；不要直接修改身份文件或移动活跃数据库。

## 2. 建模前确定用途和范围

正式反向、文档正向或资产组合之前，明确用途、完整范围/排除项、固定来源、独立要求清单与目标 L1/L2/L3。已有清晰决定可复用，范围变化或缺少决定才补充询问。参阅[内容等级指南](asset-readiness.md)。

先使用安装包中的合成示例熟悉结果。示例中的输入与决定会明确标注为合成，不授权真实项目操作。

正向示例：

> 基于这份设计文档，为图书借阅系统建模；以实现规格 L2 为目标，先展示完整范围和未决问题，再进入正式建模。

反向示例：

> 只读这个项目的指定修订和文件，以 L3 重建规格为目标；先确定完整模块范围，提取 Ontology 与 Harness，并区分源码事实、推断和待确认问题。

源码保持不变。代码并不自动确认业务含义。PDF 需要可靠文本层及页码来源；图片型 PDF 不得假装已完成 OCR。独立要求在生成规格前固定。

## 3. 审阅、发布与评定

检查原生模型、约束、规则、来源、覆盖和缺口。未知必需业务规则保持待确认。技术验证、领域决定与资产发布是不同步骤；审阅精确候选后，按原生生命周期发布。随后分别读取内容评定与重建状态。

当前 `standardVersion: "v2"` 下，`assetAssessment` 的 L3 与 `reconstructionVerification` 的 `NOT_REQUESTED` 可以同时成立。这表示规格内容完备，不表示软件已经重建或功能等价。内容授级不需要数据库、SSH 或业务 Run。

如果另行要求真实执行，才按独立流程绑定实际 provider、精确资产、来源、权限和证据。Runtime 执行成功、质量通过、业务有效与发布授权仍须分别判断。默认连接不继承 Host 的模型凭据，也不提供任意编码/部署执行器。

## 4. 继续、恢复和检查结果

跨会话时先选择插件，再提出：

> 从最近一次 Target/Loop 继续，核对源码基线是否变化，展示剩余证据。

Expert 读取私有进度和真实回执，比较基线，提出精确版本复用或新资产建议。检查点同步不是实时后台自动同步。私有 Target/Loop 文档不修改产品 Roadmap。

响应丢失时保留原 `requestId`，请求核对原回执，不重新派发不确定操作。升级前阅读[迁移指南](migration.md)。安装插件不自动连接生产服务或启用在线 worker。

成功信号：实际安装身份和工作区正确；范围、来源、目标等级可追溯；资产、评定和执行状态有各自真实记录。必需证据缺失、过期或未知时，不报告完成。

完整协议、其他工作流与边界见[原生工作流（英文）](../native-workflow.md)、[Expert 场景（英文）](../expert-scenarios.md)、[能力（英文）](../capabilities.md)、[响应联动（英文）](../response.md)。
